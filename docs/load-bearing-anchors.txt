# Headings other repositories deep-link to. Renaming one breaks their README
# silently, so this file declares them and `tests/test_docs_integrity.py` fails
# when a declared anchor no longer has a heading behind it.
#
# The obligation is inverted on purpose. The repositories that link in here are
# private and are deliberately not named in this one, so CI cannot grep them.
# What CI can do is hold this repository to a list it owns: a maintainer no
# longer has to remember to check an unnamed repository, only to leave a line in
# this file alone. Renaming a heading then fails the suite, and the fix is to
# rename the heading back or to update the consumer and this line together.
#
# It is weaker than a real cross-repository check, in one direction: a consumer
# can add a deep link that nobody declares here, and nothing will notice. A
# consuming store's own maintenance routine is where that is caught - declare
# the link here when you add it.
#
# One entry per line, `path` or `path#anchor`, relative to the repository root.
# The anchor is the GitHub heading slug, which is what a consumer's URL carries.
# Blank lines and `#` comments are ignored.
